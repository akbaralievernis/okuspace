# Okuspace Next — дорожная карта

Версия 0.2, 2026-10-15. Основание: аудит этапа 0 (локальный `docs/audit/`, не публикуется), [DECISIONS.md](DECISIONS.md).

## 1. Стратегия

**Решение пользователя (2026-10-15, ADR-0001 в [DECISIONS.md](DECISIONS.md)):** начать с чистого листа. Старый PHP-код удалён из `htdocs/` после проверенной резервной копии. Okuspace Next строится в `htdocs/` как новое приложение. Данные старого портала не переносятся (там 1 учётная запись).

- **Почему не рефакторинг.** Стек меняется целиком: PHP/MySQL → Next.js/TypeScript/PostgreSQL. Модель данных (одна группа, 3 роли, 0 FK) не подходит для многофилиальной школы. Обоснование подробно — в [PROJECT_AUDIT.md §8](audit/PROJECT_AUDIT.md).
- **Где код.** `C:\Users\user\Desktop\htdocs` — новый git-репозиторий. Выяснилось, что `htdocs` **не** был источником деплоя: старый сайт деплоится из отдельного репозитория. Очистка `htdocs` на живой сайт не влияет.
- **Хостинг.** Next.js не запускается на InfinityFree. Нужны хостинг Node.js / Next.js (Vercel, Netlify, Render или VPS) и проект Supabase **[ВОПРОС — выбор и бюджет]**.
- **Текущий PHP-сайт** продолжает работать. Ему делаются только точечные исправления безопасности (этап 0-H), новые функции туда не добавляются. Отключение — на этапе 14.
- **Что переносится как требования и референсы** (не как код): курс немецкого (видео + двуязычные субтитры + словарь + прогресс), задания и тесты, квоты AI, i18n-словари KG/RU, TOTP 2FA, уведомления. Перечень — в [CURRENT_FEATURES.md](audit/CURRENT_FEATURES.md).

## 5. Остаточные риски уровня проекта

- Объём мастер-промпта (14 этапов, 25+ сущностей) соответствует многомесячной работе команды. Реалистичный путь — поэтапные релизы с узким MVP.
- Юридические требования КР (персональные данные, видеонаблюдение, хранение данных несовершеннолетних) не проверены. Нужна консультация юриста до этапов 3 и 10.
- Без staging-окружения нельзя выполнить требование «локально → тест → production». Staging закладывается на этапе 1.
