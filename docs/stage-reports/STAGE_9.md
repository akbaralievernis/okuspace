# Отчёт: Этап 9 — Финансы

Дата: 2026-10-16. Ветка: `feat/stage-9-finance` (от `feat/stage-8-crm`).

## 1. Что сделано

**База данных** — миграция `20261021100000_finance_module` поверх ядра этапа 2 ([SCHEMA.md §11](../database/SCHEMA.md), [ADR-0011](../DECISIONS.md)):

| Требование | Реализация |
|---|---|
| Прайс-листы, тарифы | по школе или филиалу, сроки действия, статусы; цена тарифа неизменна (новая цена = новый тариф) |
| Счета | строки (тариф × количество), сумму черновика считает БД, история статусов «черновик → выставлен → аннулирован» |
| Платежи | с этапа 2; источник «сотрудник» или «провайдер»; дата в поясе школы |
| Распределение по обязательствам | не больше остатка платежа и счёта; «освобождение» с причиной вместо удаления |
| Задолженности | `invoice_balances` (к оплате, оплачено, остаток, статус), `finance_debts` |
| Скидки с разрешениями | запрос бухгалтера → утверждение руководителем; утвердить свой запрос нельзя (CHECK) |
| Возвраты | только из свободного остатка платежа; к оплаченному счёту: кредит-нота → освобождение → возврат |
| Корректировки | кредит- и дебет-ноты на выставленный счёт, с причиной и утверждением |
| Доходы и расходы | расходы по категориям со сторно (зеркальная запись с причиной, не больше одного сторно) |
| Отчёты по филиалам | `finance_report`: выставлено, получено, возвращено, доход, расходы, результат, задолженность |
| Финансовые периоды | закрытый месяц не принимает операций; открыть снова — только с причиной; аудит |
| История операций | все финансовые таблицы append-only + аудит + `invoice_status_history` |
| Онлайн-оплата | webhook `/api/payments/webhook/<provider>`: HMAC-SHA256 по сырому телу, окно 5 минут, сравнение за постоянное время, лимит 64 КБ; повтор события не создаёт платёж |

**Требования к финансовым записям:**

| Требование | Как обеспечено |
|---|---|
| Уникальные идентификаторы | `uuid` |
| Ссылки на исходную операцию | `reverses_payment_id`, `reverses_allocation_id`, `reverses_expense_id`, `invoice_id` |
| Время создания | `created_at` / `received_at` |
| Пользователь или системный источник | `created_by` / `requested_by` / `decided_by`; `source = provider` для онлайн-оплат |
| Причина корректировки | обязательна для корректировок, возвратов, освобождений, сторно, аннулирования и повторного открытия периода |
| История статусов | `invoice_status_history`, решения по корректировкам, аудит периодов |
| Защита от двойного списания и зачисления | проверки остатков под блокировкой строк; уникальные `(provider, event_id)` и `(provider, provider_ref)` |

**Интерфейс:**

- «Финансы»:
  - обзор: отчёт по филиалам за месяц, задолженности, «Ожидают утверждения», периоды;
  - счета: список, создание, карточка со строками, скидками и корректировками, выставлением, зачётом платежей, освобождением, аннулированием, историей;
  - платежи: приём с зачётом, возвраты;
  - расходы: запись, сторно;
  - прайс-листы и тарифы;
- «Оплата» для ученика и родителя: свои счета и платежи, а также счета подопечных.

**Критерии этапа:**

| Критерий | Подтверждение |
|---|---|
| Суммы проверяются на сервере | цена строки с тарифом подставляется из прайс-листа, сумма счёта считается БД (ручная правка перезаписывается); скидки не больше суммы счёта; распределения, освобождения и возвраты — не больше остатков; webhook отклоняет сумму с тремя знаками, отрицательную, в чужой валюте, по невыставленному счёту |
| Повторный webhook не дублирует платёж | БД: то же событие → `duplicate` с тем же платежом; другое событие той же операции провайдера → `duplicate`; в базе один платёж. Обработчик: повтор → 200 `duplicate`; ошибка БД → 503 (провайдер повторит безопасно) |
| Права бухгалтера и руководителя разделены | директор не может провести платёж, расход или запросить корректировку; бухгалтер не может утвердить корректировку, закрыть период или вести прайс-листы; свой запрос не утверждает никто (CHECK) |
| Отчёты сверяются с тестовыми операциями | отчёт по известным операциям (зачёт 3000, платёж 1000, возврат 400, расход 1200, ошибочный расход 300 со сторно) совпадает до копейки по каждому филиалу; менеджер филиала видит только свой филиал, администратор без финансовых прав — ничего; список должников совпадает |
| Денежные вычисления без плавающей точки | все суммы `numeric(14,2)` (инвариант схемы для каждого `amount`/`total`, включая новые таблицы); в приложении — строки и целые копейки (`BigInt`), unit-тесты (`0.10 + 0.20 = 0.30`); webhook принимает сумму только строкой |
| Проверены возвраты и корректировки | кредит-нота на оплаченный счёт отклоняется до освобождения; после освобождения → утверждение → возврат: «к оплате 4000, оплачено 4000, остаток 0, оплачен»; лишний возврат и лишнее освобождение отклоняются; дебет-нота увеличивает сумму к оплате только после утверждения; скидка блокирует выставление до решения |

**Мутационная проверка:** 9 из 9 мутаций миграции пойманы:

- нет «четырёх глаз»;
- ручная цена вместо тарифа;
- выставление с неутверждённой скидкой;
- нет проверки периода;
- webhook без защиты от повторов;
- webhook принимает три знака после точки;
- неограниченное освобождение;
- кредит по оплаченной части;
- отчёт по всем филиалам.

## 4. Остающиеся проблемы и риски

1. **Платёжный провайдер не выбран.** Webhook сделан по общей схеме HMAC и закрыт (404), пока провайдер не настроен. Нужны:
   - выбор провайдера, доступного в КР;
   - договор и тестовые ключи;
   - адаптер под формат его событий;
   - проверка на тестовом стенде провайдера.

   Кнопки «Оплатить онлайн» нет — ученик видит «оплатите в школе».
2. **Номера счетов вводятся вручную** (уникальность гарантирует БД). Автонумерацию и требования к фискальным документам (если нужны в КР) — уточнить у бухгалтера.
3. **Мультивалютность** поддержана в схеме (отчёты разбиты по валютам), но интерфейс создаёт операции в KGS.
4. **Отчёт — кассовый метод** (получено и возвращено за период) плюс «выставлено» и текущая задолженность. Начисления по методу начисления, НДС и экспорт в бухгалтерскую программу не реализованы.
5. Страницы финансов с данными в браузере не проверены (в e2e нет БД).
6. Кыргызские тексты нового раздела нужно вычитать носителю языка.
