# Отчёт: Блок A — Управление филиалами

Дата: 2026-10-17. Ветка: `feat/block-a-management` (от `feat/stage-11-notifications`).

Основание — требование клиента: директор с главного сайта управляет филиалами, ставит задачи администраторам и чётко видит выполнение. Решения — [ADR-0014](../DECISIONS.md), схема и определения показателей — [SCHEMA.md §14](../database/SCHEMA.md).

## 1. Что сделано

| Требование | Реализация |
|---|---|
| Директор ставит задачи администраторам филиалов | «Задачи» → новая задача: один или несколько исполнителей из любых филиалов, приоритет, срок. Каждый получает свою задачу и уведомление |
| Менеджер филиала ставит задачи своим сотрудникам | то же, но только сотрудникам своего филиала |
| Чёткий контроль выполнения | статусы: новая → в работе → на проверке → выполнена (или возвращена на доработку, или отменена). Отчёт исполнителя обязателен. Принимает автор или директор, но не сам исполнитель. Вся история неизменна |
| Видно, кто не выполнил | рассылка показывает «выполнено X из Y»; просроченные отмечены; напоминание о просрочке исполнителю и автору (один раз) |
| Обсуждение по задаче | комментарии исполнителя и руководителя, уведомление другой стороне |
| Объявления | директор — всей школе или филиалу; менеджер и администратор — своему филиалу. Выбор ролей получателей (сотрудники, преподаватели, ученики, родители) |
| Подтверждение ознакомления | по желанию автора; видно, кто прочитал и кто подтвердил. Текст после публикации не меняется |
| Панель директора | все филиалы рядом за выбранный период: ученики, группы, преподаватели, занятия, **занятия без отметок**, посещаемость, работы на проверке, обращения и записи, задачи, ознакомление, поступления и долги. Проблемные цифры выделены. Определения показателей — на странице |
| На главной кабинета | «Открытых задач у вас: N», «Объявлений ждут подтверждения: N» |

**Права.** Три новых права:

- `task.manage` — директор, менеджер филиала;
- `announcement.publish` — директор, менеджер, администратор;
- `dashboard.read` — директор, менеджер, администратор.

Ставить задачи и публиковать объявления можно только с MFA. Администратор видит панель своего филиала без финансов: прав на финансы у него нет.

**Демо-данные** дополнены: рассылка задачи в два филиала, задачи менеджеру и бухгалтеру, два объявления (одно с подтверждением).

**Что проверено тестами БД:**

- кто может ставить задачи и кому: MFA, свой филиал, только сотрудники; не ученик, не родитель, не сам себе, не чужая школа;
- кто видит задачи: исполнитель, руководитель филиала, директор; остальные — нет;
- полный цикл задачи с возвратом на доработку; история в правильном порядке и неизменна;
- менеджер не принимает чужую директорскую задачу; исполнитель не принимает свою, даже если позже получил права директора;
- напоминания о просрочке без дублей; пользователи не могут запустить их вручную;
- получатели объявлений точно по филиалу и ролям; публикация только в своём охвате;
- квитанции видит только сам получатель; статистику — только публикующие в охвате;
- подтверждение — только если запрошено; текст неизменен; удалить нельзя, только в архив;
- панель: каждый показатель сверен с прямым запросом к данным, финансы — с финансовым отчётом этапа 9; финансы скрыты без права; чужой филиал и чужая школа не видны.

**Мутационная проверка:** 15 из 15 мутаций миграции пойманы:

- без MFA;
- без проверки филиала;
- любая роль исполнителя;
- приёмка своей задачи;
- приёмка любым менеджером;
- сдача без отчёта;
- задачи видны всем;
- объявление уходит во все филиалы;
- подтверждение без запроса;
- изменяемый текст объявления;
- утечка финансов на панели;
- панель всех филиалов;
- дубли напоминаний;
- изменяемая история;
- квитанции видны всем;
- неверный подсчёт «без отметок».

Последнюю мутацию из списка («приёмка своей задачи») тесты сначала не ловили. Добавлен тест: исполнитель повышен до директора и всё равно не может принять свою задачу. После этого мутация поймана.

## 4. Остающиеся проблемы и риски

1. **На настоящем Supabase не проверено** — как и всё остальное; первый запуск — демо-стенд.
2. Страницы с данными в браузере не проверены (в e2e нет БД).
3. Нет вложений к задачам и отчётам (фото, файлы): в проекте ещё нет хранилища файлов.
4. Нет повторяющихся задач («каждый понедельник») и шаблонов задач.
5. Если у руководителя несколько школ, форма задачи и панель работают с первой школой; на панели школа выбирается параметром адреса.
6. Объявление с очень большим числом получателей показывает список первых 500. Цифры статистики при этом точные.
7. Кыргызские тексты нового раздела нужно вычитать носителю языка.
