| Замену преподавателя не оформить | На странице занятия — «Замена преподавателя» с причиной. Ученики видят изменение, заменяющий получает уведомление и может отметить посещаемость. Список группы ему виден только около даты занятия |

**Проверено тестами БД:**

*Счета*
- нужны MFA и `finance.write`;
- три записи — три черновика с правильными суммами (6000 по прайсу школы, 5500 по прайсу филиала Ош), номера подряд, срок 10-е;
- курс без тарифа — в списке, без счёта;
- повтор — 0 новых;
- счёт с неутверждённой скидкой остаётся черновиком, остальные выставлены;
- после аннулирования счёт формируется заново;
- дубль напрямую — отказ;
- бухгалтер одного филиала выставляет только своему.

*Зарплата*
- ставки ставят только финансы с MFA, только активным преподавателям; изменить нельзя;
- ведомость: 500 + 500 + 700 = 1700 (с 15-го действует ставка филиала);
- отменённое занятие не считается;
- преподаватель без ставки — в списке;
- черновик не виден преподавателю;
- утвердить может руководитель, но не бухгалтер, преподаватель или кто-то без MFA; автор расчёта не утверждает свою ведомость, даже имея оба права;
- после утверждения новые занятия ведомость не меняют, изменить и удалить её нельзя;
- выплата — один раз, расход «зарплата» 1700.

*Отработки*
- пропуск → заявка, исправление → закрыта, уважительная → снова открыта;
- назначает только сотрудник своего филиала: не прошедшее занятие (даже не отмеченное), не другой филиал, не то же самое;
- уведомления ученику и родителю;
- «отработано» — один раз, отмена — с причиной;
- видимость: 6 ролей «да», 4 «нет».

*Замена*
- назначает только расписание филиала, с причиной, только активный преподаватель филиала;
- прошедшее занятие нельзя; обойти функцию прямым изменением нельзя;
- заменяющий видит список и отмечает посещаемость;
- замена через 5 дней: само занятие видно, список и профили — ещё нет;
- возврат преподавателя группы снимает замену и доступ.

**Мутационная проверка:** 21 из 22 мутаций миграции пойманы. Не поймана одна: «убрать проверку, что утверждает не автор». Это эквивалентная мутация — то же правило закреплено ограничением таблицы, тест проверяет поведение. Три мутации тесты сначала пропускали; на них добавлены проверки:

- счета чужого филиала;
- самоутверждение;
- прошедшее неотмеченное занятие.

## 4. Остающиеся проблемы и риски

1. **Импорт учеников и учителей из Excel не сделан** — нужно ваше решение. Вход в систему сейчас по email, а у многих учеников его нет. Варианты:
   - (а) вход по номеру телефона — нужен SMS-провайдер, платно;
   - (б) администратор создаёт учётную запись с логином вида `aidana.mamatova@ad.okuspace` и временным паролем, ученик меняет пароль при первом входе — бесплатно, работает без email;
   - (в) импорт только тех, у кого есть email (приглашение по ссылке).

   Мой совет — (б).
2. Правила оплаты учителей не подтверждены — сейчас ставка за занятие. Почасовая ставка или ставка за ученика — доработка.
3. Нет пропорционального счёта при записи в середине месяца; скидки — через существующие корректировки.
4. Отработка не создаёт отметку посещаемости в чужой группе — «Отработано» ставится вручную.
5. На настоящем Supabase не проверено; страницы с данными в браузере не проверены (в e2e нет БД).
6. Нестабильность локального e2e-сервера сохраняется.
7. Кыргызские тексты нужно вычитать носителю языка.
