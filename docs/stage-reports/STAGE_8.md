# Отчёт: Этап 8 — CRM и продажи

Дата: 2026-10-16. Ветка: `feat/stage-8-crm` (от `feat/stage-7-ai-lab`).

## 1. Что сделано

**База данных** — миграция `20261020100000_crm` ([SCHEMA.md §10](../database/SCHEMA.md), [ADR-0010](../DECISIONS.md)):

| Требование | Реализация |
|---|---|
| Заявки с сайта | `submit_lead_request` (этап 4) теперь сразу создаёт или находит контакт CRM, пишет событие «Заявка с сайта», а для пробного урока — бронь и этап «Записан на пробный» |
| Контакты и история общения | `crm_contacts`; звонки, сообщения, встречи, заметки с каналом (телефон, WhatsApp, Telegram, email, SMS, лично) |
| Источник обращения | звонок, пришёл в школу, рекомендация, соцсети, сайт (пробный / вопрос), импорт, другое; отчёт по источникам |
| Запись на пробный урок | из CRM (`crm_book_trial`) — те же места, что и с сайта; итог: пришёл / не пришёл / отменено |
| Статусы и история переходов | этапы «Новый → Связались → Записан на пробный → Был на пробном → Предложение → Ученик» и «Отказ» (с причиной); каждая смена пишется триггером |
| Назначение менеджера | только сотрудник продаж филиала контакта (проверка в БД) |
| Напоминания о звонках | исполнитель, срок в поясе филиала, «Мои напоминания» с просроченными |
| Конверсия в ученика | `crm_convert` связывает контакт с учётной записью ученика филиала; воронка за 30 дней с долей ставших учениками |
| Запись на курс | `crm_enroll` из карточки контакта (с проверкой прав на запись и вместимости группы) |
| Импорт и экспорт с контролем прав | импорт CSV (до 500 строк, дубли пропускаются) — `lead.manage`; экспорт — только `crm.admin` + MFA, свой охват, минимальные поля, журнал выгрузок |
| Защита от повторного создания | нормализация телефона и email + уникальные индексы; повторная заявка того же человека с сайта не создаёт новый контакт |
| Не раскрывать лишнее | контакты видят только сотрудники продаж своего филиала; преподаватели, бухгалтеры, ученики — нет; в экспорте нет заметок и истории |
| Хранение и удаление по запросу | `crm_erase` обезличивает контакт, историю, напоминания и удаляет исходные заявки; `crm_purge_stale` — автоматическое обезличивание через 24 месяца без активности |

**Интерфейс:**

- «CRM» — воронка, «Мои напоминания», фильтры (этап, менеджер, поиск по имени, телефону, email), список контактов, новый контакт;
- карточка контакта:
  - данные, этап, менеджер;
  - запись общения, напоминания;
  - пробный урок, конверсия, запись в группу;
  - заявки с сайта, история;
  - удаление по запросу (с подтверждением);
- «Импорт из CSV»: файл или вставка текста, ru/ky/en-заголовки, «,» или «;»;
- выгрузка CSV `/app/crm/export`:
  - формулы нейтрализуются (защита от CSV injection);
  - BOM, чтобы кириллица правильно открывалась в Excel;
  - `Cache-Control: no-store`;
- на странице «Заявки» — ссылка «Открыть в CRM».

**Критерии этапа:**

| Критерий | Подтверждение |
|---|---|
| Заявка проходит полный рабочий процесс | security-тест: заявка с сайта → контакт и бронь → менеджер → звонок → напоминание → «пришёл на пробный» → предложение → ученик → запись в группу. Повторная запись в ту же группу отклоняется |
| Статусы и история сохраняются | тот же тест сверяет всю историю (12 событий по порядку, с этапами «было → стало»); нельзя поставить «Ученик» без конверсии и «Отказ» без причины; системные события, чужое имя автора, правка и удаление истории отклоняются |
| Повторная отправка не создаёт дубликаты | та же форма → та же заявка; тот же телефон в другом формате или тот же email в другом регистре → тот же контакт; ручное создание с тем же номером отклоняется; импорт пропускает дубли с базой и внутри файла |
| Доступ проверяется на сервере | RLS и функции БД: продажи своего филиала видят и меняют контакты; другой филиал, преподаватель, бухгалтер, ученик, другая школа — нет; без MFA изменения не проходят; менеджер — только сотрудник продаж филиала; экспорт и удаление — только `crm.admin` |
| Экспорт не раскрывает лишние данные | экспорт содержит ровно 9 рабочих полей (проверка набора ключей), без заметок и текстов общения; менеджер филиала выгружает только свой филиал; продажи, администратор, другая школа и вход без MFA — отказ; каждая выгрузка записана в журнал; в CSV формулы нейтрализованы (unit-тест) |

**Мутационная проверка:** 8 из 8 мутаций миграции пойманы тестами:

- без нормализации телефона;
- заявка всегда создаёт новый контакт;
- нет истории этапов;
- экспорт без MFA;
- заметки в экспорте;
- удаление не обезличивает историю;
- контакты видны всей школе;
- брони CRM не занимают места.

## 4. Остающиеся проблемы и риски

1. **Срок хранения 24 месяца — предложение.** Его и текст основания для удаления должен утвердить юрист (закон КР о персональных данных). Запуск `crm_purge_stale` по расписанию — этап 13.
2. **Учётную запись ученика CRM не создаёт.** Конверсия связывает контакт с уже существующим учеником; приглашение ученика — раздел «Участники» (приглашения по ссылке, этап 3). Автоматическое приглашение из CRM — после выбора канала доставки (этап 11).
3. **Напоминания только в кабинете.** Уведомления менеджеру по email или в мессенджер — этап 11.
4. Контакты без филиала (вопрос с сайта без выбора филиала) видят только сотрудники уровня школы — так же, как заявки на этапе 4.
5. В выгрузке номер телефона начинается с апострофа (`'+996…`): это защита от формул в Excel.
6. Отрисовка страниц CRM с данными в браузере не проверена (в e2e нет БД).
7. Кыргызские тексты нового раздела нужно вычитать носителю языка.
