# Отчёт: Этап 4 — Дизайн-система и публичный сайт

Дата: 2026-10-16. Ветка: `feat/stage-4-site` (от `main` с этапами 0–3). Изменения не закоммичены.

## 1. Что сделано

**Дизайн-система** ([DESIGN_SYSTEM.md](../architecture/DESIGN_SYSTEM.md)):

- токены цветов с проверенным контрастом, типографика, отступы, радиусы, цель нажатия 44 px;
- кнопки, поля (`Field` / `Select` / `Textarea` / `Checkbox`), уведомления, пустые состояния, бейджи, карточки, skeleton;
- доступный диалог подтверждения (`<dialog>`) — он заменил `window.confirm` из этапа 3;
- безопасный `RichText` без HTML;
- шапка, подвал, мобильное меню;
- граница ошибок без stack trace.

**Публичный сайт** (ky / ru / en), 15 страниц:

- главная;
- каталог с фильтрами (GET-форма, работает без JS, фильтры сохраняются при смене языка);
- страница курса;
- уровни (CEFR A1–C2);
- филиалы;
- преподаватели;
- цены;
- пробный урок (запись на слот);
- контакты (форма вопроса);
- «О школе», FAQ;
- политика конфиденциальности, правила, согласие на обработку ПДн;
- вход, регистрация.

**Данные — только из БД** (ADR-0005), миграция `20261016100000_public_site`:

- аноним читает только через 7 функций `public_*`, они отдают опубликованные данные без ПДн;
- юридические документы версионируются, опубликованная редакция неизменна;
- **регистрация и заявки закрыты, пока документы не опубликованы**; согласие записывается на конкретную версию документов конкретной школы. Это закрывает пункт 4.2 отчёта этапа 3;
- заявки сохраняются только сервером: идемпотентность, вместимость слота, проверка версии согласия, лимиты, поле-ловушка для ботов;
- профиль преподавателя публикует только сам преподаватель.

**Инструменты сотрудников:**

- «Сайт» — страницы и юридические документы: черновик → публикация с подтверждением;
- «Заявки» — входящие в пределах своего охвата, смена статуса;
- «Пробные уроки» — слоты, время задаётся в часовом поясе филиала;
- «Публичный профиль» преподавателя;
- меню кабинета показывает только разделы, к которым у пользователя есть доступ.

**Новая dev-зависимость:** `@axe-core/playwright@4.13.0` (ADR-0006).

## 4. Остающиеся проблемы и риски

1. **Нет реального контента.** Тексты «О школе», FAQ, контакты, юридические документы, филиалы, курсы и цены должна внести школа. До этого сайт показывает честные пустые состояния. **Тексты юридических документов должен подготовить или проверить юрист** (закон КР о персональных данных) — я их не писал.
2. **Отрисовка страниц с реальными данными в e2e не проверена**: в e2e нет БД. Покрыто:
   - ответы `public_*` на настоящем Postgres проходят TS-схемы сайта (integration);
   - логика фильтров и форматирования — unit.

   Полный визуальный прогон с данными — на тестовом проекте Supabase, вместе со шлюзами этапов 2–3.
3. **Каталог и цены** до этапа 5 публикуются только через SQL: управления курсами в кабинете ещё нет.
4. **Ручная проверка доступности** экранным диктором не проводилась; axe ловит лишь часть проблем.
5. **Кыргызские тексты** (включая описания CEFR) нужно вычитать носителю языка.
6. **Производительность:** публичные страницы рендерятся динамически (nonce CSP), кеширования данных пока нет. Для сотен посетителей это приемлемо; кеш — на этапе 13.
7. Время слотов вводится в поясе филиала (`Asia/Bishkek`). Переходы на летнее время обработаны, но для КР не актуальны.
