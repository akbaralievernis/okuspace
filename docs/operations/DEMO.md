# Демо-стенд для показа клиенту

Цель — рабочая онлайн-ссылка с вымышленной школой: публичный сайт и кабинеты всех ролей. Используются бесплатные тарифы Supabase и Vercel.

> Это **демо, не production**. Все люди, телефоны и документы вымышлены, юридические тексты помечены «демо». Email и Telegram не подключены, AI и мониторинг выключены. Реальные данные учеников сюда не вносить.

Время: около 30–40 минут. Ниже: **[вы]** — действия в браузере или на своём компьютере; ключи никому не пересылайте, в том числе в чат.

---

## Шаг 1. Проект Supabase [вы]

1. Зарегистрируйтесь на https://supabase.com (можно через GitHub).
2. **New project**:
   - Name: `okuspace-demo`;
   - Database password: сгенерируйте и сохраните у себя (для демо он больше не понадобится);
   - Region: **Central EU (Frankfurt)**.
3. Дождитесь, пока проект создастся (1–2 минуты).
4. Откройте **Project Settings → API Keys** и **Project Settings → Data API** и найдите там три значения:
   - Project URL (`https://xxxx.supabase.co`);
   - **Publishable key** (`sb_publishable_…`);
   - **Secret key** (`sb_secret_…`) — это секрет: только в `.env.local` и в Vercel.

## Шаг 2. Структура базы [вы]

1. В папке проекта выполните:

   ```bash
   npm run demo:sql
   ```

   Появятся два файла в `supabase/demo/out/`.
2. Supabase → **SQL Editor** → New query.
3. Откройте `supabase/demo/out/1-migrations.sql` в Блокноте, нажмите `Ctrl+A`, `Ctrl+C`, вставьте в редактор и нажмите **Run**. Ожидаемый результат — `Success. No rows returned`.
4. Если появилась ошибка, сделайте скриншот и пришлите его. Файл выполняется целиком или не выполняется совсем, поэтому после исправления его можно просто запустить снова.

## Шаг 3. Демо-пользователи [вы]

1. Создайте в корне проекта файл `.env.local` (он в `.gitignore` и в репозиторий не попадёт):

   ```
   NEXT_PUBLIC_APP_URL=http://localhost:3000
   NEXT_PUBLIC_SUPABASE_URL=<Project URL>
   NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=<Publishable key>
   SUPABASE_SECRET_KEY=<Secret key>
   SITE_ORGANIZATION_SLUG=demo
   ```

2. Выполните:

   ```bash
   npm run demo:users
   ```

   Скрипт создаст 11 пользователей со случайными паролями. Пароли — в `supabase/demo/out/demo-accounts.txt` (только на вашем компьютере). Повторный запуск выдаёт новые пароли.

## Шаг 4. Демо-данные [вы]

В SQL Editor откройте новый запрос и вставьте `supabase/demo/out/2-demo-data.sql` → **Run**. В ответе: «Демо-данные загружены», число занятий и уведомлений.

Даты считаются от дня загрузки: две недели прошедших занятий с посещаемостью и две недели вперёд. Если показ будет нескоро, загрузите данные ближе к нему: создайте новый проект Supabase или попросите скрипт очистки.

## Шаг 5. Настройки входа в Supabase [вы]

**Authentication → Sign In / Providers → Email:**

- Email provider включён;
- Minimum password length: `10`.

**Authentication → Multi-Factor:** TOTP включён (по умолчанию так и есть).

URL-адреса — после шага 6, когда будет известен адрес на Vercel.

## Шаг 6. Публикация на Vercel [вы]

1. Зарегистрируйтесь на https://vercel.com через GitHub.
2. **Add New → Project** → импортируйте репозиторий `akbaralievernis/okuspace`.
3. В **Environment Variables** добавьте:

   | Имя | Значение |
   |---|---|
   | `NEXT_PUBLIC_APP_URL` | `https://<имя-проекта>.vercel.app` (Vercel покажет имя; если не совпадёт — исправьте и сделайте Redeploy) |
   | `NEXT_PUBLIC_SUPABASE_URL` | Project URL |
   | `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Publishable key |
   | `SUPABASE_SECRET_KEY` | Secret key |
   | `SITE_ORGANIZATION_SLUG` | `demo` |
   | `CRON_SECRET` | результат команды ниже |

   Команда для `CRON_SECRET`:

   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```

4. **Deploy.**
5. **Settings → Git → Production Branch**: укажите `feat/stage-11-notifications`, иначе опубликуется старая ветка `main` (этап 3). Затем **Deployments → Redeploy** последнего деплоя этой ветки.

## Шаг 7. Адрес сайта в Supabase [вы]

Supabase → **Authentication → URL Configuration**:

- Site URL: `https://<имя-проекта>.vercel.app`;
- Redirect URLs: `https://<имя-проекта>.vercel.app/ru/**`, `…/ky/**`, `…/en/**`.

## Шаг 8. Проверка [вы]

1. Откройте `https://<имя-проекта>.vercel.app/ru`: должен быть сайт «Okuspace Demo School» с курсами и преподавателями.
2. Войдите как директор (данные — в `demo-accounts.txt`).
3. **Сотрудникам нужен второй фактор.** Директор, менеджер филиала, администратор, бухгалтер и менеджер по продажам при первом входе подключают приложение-аутентификатор (Google Authenticator, Microsoft Authenticator и т. п.): отсканировать QR-код и ввести 6-значный код. Так защищён доступ к данным школы. Все пять аккаунтов можно добавить в одно приложение на вашем телефоне — сделайте это до показа. Преподаватели, ученики и родители входят только по паролю.

## Что показывать (сценарий на 15 минут)

| Кто | Что открыть | Что видно |
|---|---|---|
| Гость | `/ru`, «Курсы», «Преподаватели», «Пробное занятие» | публичный сайт из данных школы; запись на пробное попадает в CRM |
| Директор | Панель | показатели обоих филиалов рядом: занятия, посещаемость, долги, задачи; «без отметок» и просрочки выделены |
| Директор | Задачи | рассылка «Проверить журналы» в два филиала: у администратора «в работе», у преподавателя в Оше «новая»; поставить новую задачу |
| Директор | Объявления | объявление филиалу «Центр» с подтверждением: кто прочитал и кто подтвердил |
| Администратор | Задачи → задача | сдать отчёт; директор принимает или возвращает на доработку |
| Директор | Главная → CRM | воронка: новые, связались, предложение, отказ с причиной; напоминание менеджеру |
| Директор | Финансы | счета: оплачен, частично оплачен и просрочен, срок через 3 дня; платежи, расходы, отчёт |
| Директор / менеджер | Уведомления | предупреждение «два пропуска подряд» у Эрлана |
| Менеджер филиала | Расписание | занятия на 4 недели, аудитории, конфликты |
| Преподаватель (Sarah) | Группы → EN-A2, Расписание → занятие | журнал посещаемости, работы учеников, проверка с оценкой |
| Преподаватель (Sarah) | Группы → EN-A2 → Экзамены, Журнал и итоги месяца | баллы за экзамен; итоги месяца посчитаны автоматически — «Пересчитать», комментарий, «Опубликовать» |
| Преподаватель (Sarah) | Группы → EN-A2 → новое задание | задание всей группе или только выбранным ученикам |
| Директор | Панель → Правила итоговой оценки | веса частей и шкала |
| Ученица (Айдана) | Обучение → курс, тест, домашнее задание | уроки со словарём, тест с автопроверкой, оценка 9/10 с комментарием |
| Родитель | Оплата, Уведомления | счёт ребёнка, результаты и пропуски |
| Любой | Уведомления → Настройки уведомлений | что можно выключить и что нет (важное) |

Чего в демо нет (честно сказать клиенту):

- письма и Telegram не отправляются — провайдеры не выбраны;
- AI-лаборатория выключена до проверки качества;
- мониторинг аудиторий выключен до юридической проверки;
- онлайн-оплата не подключена;
- кыргызские тексты ещё вычитывает носитель языка.

## Безопасность демо

- Публичная форма заявки работает: всё, что в неё введут, сохранится в CRM демо-школы. На показе вводите вымышленные данные.
- После показа: Vercel → проект → Settings → **Pause**, или удалите проект. Supabase → **Pause project**.
- `supabase/demo/out/` (пароли) и `.env.local` (ключи) не коммитятся — это закреплено в `.gitignore`.
