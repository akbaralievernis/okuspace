# Окружения, развёртывание и резервное копирование

Статус: **предложение этапа 1**. Выбор хостинга ждёт решения — см. ADR-0003 в [../DECISIONS.md](../DECISIONS.md).

## 1. Окружения

| Окружение | Приложение | База / Auth / Storage | Данные | Кто деплоит |
|---|---|---|---|---|
| development | `npm run dev` локально | Supabase local (нужен Docker) или dev-проект | только `seed.sql` | разработчик |
| test (CI) | `next build && next start` в GitHub Actions | временная БД (см. TESTING_STRATEGY §2) | фабрики тестов | CI |
| staging | Vercel Preview / отдельный проект (ветка `develop`) | Supabase-проект `okuspace-staging` | синтетические данные | CI после зелёных проверок |
| production | Vercel Production (ветка `main`) | Supabase-проект `okuspace-prod`, тариф с PITR | реальные данные | CI + **ручное подтверждение** |

**Правила:**

- У каждого окружения свои ключи. Ключи production не используются нигде больше.
- `SUPABASE_SERVICE_ROLE_KEY` задаётся только в серверном env хостинга и никогда не получает префикс `NEXT_PUBLIC_`.
- Миграции применяются в порядке test → staging → production. В production — только через CI (`supabase db push`) после резервной копии.

## 2. Конвейер CI (`.github/workflows/ci.yml`)

1. `npm ci`
2. `npm run typecheck`
3. `npm run lint`
4. `npm run test` (unit)
5. `npm run build`
6. `npm run check:bundle` (секреты в клиентской сборке)
7. `npm run test:e2e`
8. `npm audit --audit-level=high` (сообщает об уязвимостях, решение — по отчёту)

С этапа 2 добавятся проверка миграций на чистой БД и тесты RLS.

## 3. Резервное копирование (детально — этап 13)

- **Production:** ежедневные бэкапы Supabase + PITR (на платном тарифе). Дополнительно — еженедельный `pg_dump` в отдельное зашифрованное хранилище, срок хранения 30 дней.
- **Storage:** версионирование или периодическая копия bucket'ов.
- **Проверка восстановления:** раз в месяц восстановить дамп в staging и прогнать smoke-тесты. Результат записывается в журнал.
- Перед каждой разрушающей миграцией обязателен ручной бэкап.

## 4. Откат

- Приложение: на Vercel — «Instant Rollback» на предыдущий деплой.
- БД: миграции только вперёд. Откат делается корректирующей миграцией или восстановлением PITR (только при инциденте, с записью в журнал).

## 5. Старый сайт okuspace.rf.gd

Старый сайт работает отдельно и **не связан** с этим конвейером. План его отключения — на этапе 14.
