# Стратегия тестирования

## 1. Уровни

| Уровень | Инструмент | Где | Что проверяет | Когда запускается |
|---|---|---|---|---|
| Статика | `tsc --noEmit` (strict), ESLint (`next/core-web-vitals`, `next/typescript`, jsx-a11y) | весь `src/` | типы, ошибки, базовая доступность | каждый коммит / CI |
| Unit | Vitest | `tests/unit` | чистые функции: валидация (Zod), env, i18n, ошибки, логгер, расчёты денег и прав | CI |
| Integration | Vitest + реальный Postgres | `tests/integration` | серверные сервисы и SQL-функции на настоящей БД с миграциями | CI (с этапа 2) |
| Security / RLS | Vitest + Postgres, клиенты под разными JWT | `tests/security` | негативные сценарии: чужой профиль, филиал, группа, работа, оплата, tenant; повышение прав; таблицы без RLS | CI (с этапа 2), **блокирует релиз** |
| E2E | Playwright (Chromium, мобильный и десктопный viewport) | `tests/e2e` | критические сценарии пользователя, заголовки безопасности, адаптивность | CI |
| Сборка | `scripts/check-client-bundle.mjs` | `.next/static` | в клиентском JS нет серверных секретов и их имён | CI после `build` |

## 2. Тестовая БД для RLS — нужно решение на этапе 2

Docker на этой машине не установлен, поэтому локальный стек Supabase (`supabase start`) недоступен. Варианты:

1. Установить Docker Desktop. Самый точный вариант: локально работают Auth, Storage и тот же Postgres, что в production. **Рекомендуется.**
2. Отдельный облачный Supabase-проект `okuspace-test`, который очищается перед прогоном. Только для CI, без реальных данных.
3. PGlite (Postgres в WASM) для быстрых тестов схемы и RLS через `SET ROLE` / `request.jwt.claims`. Не покрывает Auth и Storage.

**Решение (этап 2): вариант 3 — PGlite**, см. ADR-0004 в `docs/DECISIONS.md`. Варианты 1 или 2 обязательны перед staging.

## 3. Правила

- Тест, который упал, не удаляют и не помечают `skip` без записи в отчёте этапа с причиной.
- Каждый найденный дефект безопасности получает регрессионный тест.
- Реальные персональные данные в тестах не используются. Фабрики генерируют данные, email — на домене `example.test`.
- Тесты не обращаются к внешним AI- и платёжным API: используются адаптеры-заглушки, а режим «провайдер недоступен» проверяется отдельным тестом.
- Время в тестах фиксировано (`vi.setSystemTime`), часовые пояса проверяются явно (`Asia/Bishkek`, UTC, переход через полночь).

## 4. Покрытие по этапам (минимум)

| Этап | Обязательные тесты |
|---|---|
| 1 | unit: env, i18n, errors, logger-redaction; e2e: главная во всех локалях, переключатель языка, заголовки безопасности, `/api/health`, отсутствие горизонтальной прокрутки на 375 px; проверка бандла |
| 2 | RLS-матрица «роль × таблица × операция», все негативные сценарии из мастер-промпта, проверка «нет таблиц без RLS» |
| 3 | вход, выход, восстановление пароля, приглашение, блокировка, повышение прав, межфилиальный доступ |
| 5+ | E2E-сценарии этапов, идемпотентность повторной отправки |
