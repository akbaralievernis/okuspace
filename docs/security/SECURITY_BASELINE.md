# Базовые критерии безопасности

Это обязательные критерии для всех этапов. Если критерий нарушен, этап не может получить статус PASSED. Справа указано, где критерий проверяется.

| # | Критерий | Проверка |
|---|---|---|
| B-01 | Секреты не попадают в клиентскую сборку и в репозиторий | `scripts/check-client-bundle.mjs`; `.gitignore`; секреты только в env хостинга |
| B-02 | Серверный код помечен `server-only` | сборка падает при импорте в клиентский компонент |
| B-03 | Весь ввод проходит Zod-валидацию на сервере | ревью + unit-тесты схем |
| B-04 | Права проверяются на сервере и в RLS; клиенту не доверяем | тесты `tests/security` (с этапа 2) |
| B-05 | RLS включён на всех таблицах с данными | тест к `pg_class.relrowsecurity` (с этапа 2) |
| B-06 | Пользователь не может повысить себе права | негативный тест (этап 3) |
| B-07 | CSP с nonce, без `unsafe-eval` в production; HSTS; `X-Content-Type-Options: nosniff`; `Referrer-Policy`; `Permissions-Policy`; `frame-ancestors 'none'` | e2e-тест заголовков (этап 1) |
| B-08 | Пароли, токены, ключи и полные персональные данные не пишутся в логи | unit-тест редакции логгера |
| B-09 | Пользовательские файлы лежат в приватных bucket'ах, доступ — по подписанным URL с коротким сроком; HTML и SVG не отдаются как исполняемый контент | этап 2/5 |
| B-10 | Webhook'и: проверка подписи + идемпотентность (`UNIQUE(provider, event_id)`) | этап 9 |
| B-11 | Финансовые записи и журнал аудита append-only | тест на запрет UPDATE/DELETE (этап 2/9) |
| B-12 | Rate limit на вход, регистрацию, сброс пароля, AI — на сервере | этап 3/7 |
| B-13 | Сторонние скрипты не подключаются с CDN. Зависимости зафиксированы lock-файлом, проходят `npm audit` | CI |
| B-14 | Production-ошибки не раскрывают stack trace и SQL | e2e/unit (`toPublicError`) |
| B-15 | Тестовые аккаунты и seed-данные отсутствуют в production | чек-лист этапа 14 |

Уроки аудита старого проекта (локальный отчёт `docs/audit/`, не публикуется) учтены в критериях выше и в [AUTH_FLOWS.md](../architecture/AUTH_FLOWS.md).
